# polymarket-tech

## Summary
Polymarket's bot ecosystem went through a hard reset in H1 2026 that any new roadmap must treat as ground truth. On April 28, 2026 Polymarket cut over to CLOB V2: new smart contracts (ctf-exchange-v2), a rewritten order book, order books cleared during the maintenance window, and a new collateral token — pUSD, an ERC-20 on Polygon backed 1:1 by native USDC — replacing bridged USDC.e. V1-signed orders and the legacy SDKs (py-clob-client, clob-client) no longer work in production; both repos are archived (May 2026) and Polymarket now points builders at py-clob-client-v2 / clob-client-v2 and, for new projects, the unified SDKs Polymarket/py-sdk and Polymarket/ts-sdk (Gamma + Data + CLOB + WebSockets in one package). Order signing changed concretely: `nonce`, `feeRateBps` and `taker` fields were removed, `timestamp` (ms), `metadata` and `builder` were added, and the EIP-712 Exchange domain moved to version "2" while the L1 ClobAuthDomain stays at version "1" (chainId 137). Auth remains two-layer: L1 = one-time EIP-712 wallet signature that derives apiKey/secret/passphrase; L2 = HMAC-SHA256 headers on every authenticated request (Unix seconds). negRisk (multi-outcome) markets still require a different verifyingContract (neg-risk-ctf-adapter) — bots must read the `neg_risk` flag before signing or orders are rejected. Order types: GTC, GTD, FOK, FAK. Rate limits are Cloudflare-enforced sliding windows (15,000 req/10s global; POST /order 3,500/10s burst + 36,000/10min sustained; batch books/prices 500/10s; Gamma 4,000/10s; Data API 1,000/10s), with a Builder Program (unverified/verified/partner tiers via builder@polymarket.com) unlocking higher throughput.

The second structural change is fees. Polymarket (global) traded fee-free through 2025, then rolled out taker fees in phases: crypto markets Jan 5, 2026; sports Feb 18; nearly all categories Mar 30, 2026, with geopolitics/world-events permanently fee-free. The formula is dynamic — fee = C × p × feeRate × (p(1−p))^exponent, peaking at p=0.5 — with peak effective taker fees of ~1.80% (crypto), 0.75% (sports), 1.00% (finance/politics), 1.50% (economics), 1.25% (culture/weather). Makers pay zero and a category-specific share of taker fees (20% crypto, 25% most, 50% finance) funds a Maker Rebates Program paid daily pro-rata to filled maker volume. This stacks with the older Liquidity Rewards Program: daily pUSD payouts at ~midnight UTC for resting limit orders near the midpoint, quadratic scoring (closer = disproportionately more), per-market min-size and max-spread parameters readable via API, a 3x penalty for one-sided quoting when the midpoint is 0.10–0.90, and a $1/day minimum payout that does not roll over. Reward farming + rebate farming is exactly what community MM bots (warproxxx/poly-maker and its forks) are built to do; the binding risk is adverse selection — one transparent operator (kachence/polymm, a sports de-vig MM with a public wallet, ~$5k net in early 2026) documented +$8,293 of theoretical arb eaten down by −$3,184 of adverse-selection losses on unhedged residuals, and retired his Python bot because it was "too slow to defend its edge," moving to a private Rust rewrite.

The community bot landscape clusters into five strategy families, all with public GitHub exemplars: (1) intra-market arbitrage — YES+NO < $1 in binaries and negRisk rebalancing in multi-outcome markets; the IMDEA Networks study of 86M bets (Apr 2024–Apr 2025) measured $39.59M total arbitrage extraction, of which negRisk rebalancing was $28.99M (~73%) across only 662 markets vs $10.58M across 7,051 single-condition markets (claimed ~29× capital efficiency), and found ~73% of profits went to sub-100ms bots; (2) cross-venue arbitrage — Polymarket vs Kalshi (ImMike/polymarket-arbitrage watches 10,000+ markets; CarlosIbCu's BTC-1-hour bot) and Polymarket vs de-vigged bookmaker odds via The Odds API (kachence/polymm, CrewSX); (3) copy-trading/whale-tracking via the public Data API (positions/trades/leaderboard endpoints) — Xyryllium/polymarket-tracker-bot is a notable Discord-based one with built-in paper trading; (4) latency/news bots on short-duration crypto up/down markets exploiting the 2–10s lag between Binance spot and Polymarket odds (learningworship/polymarket-latency-bot); (5) LLM/agent trading — the official Polymarket/agents framework (3.8k stars) was archived May 2026 and effectively replaced by Polymarket/agent-skills (Claude-oriented skill docs covering auth, trading, websockets, token ops) plus the Rust polymarket-cli (2.8k stars, explicit JSON-output agent mode) and a crop of community MCP servers. Caveat: GitHub is flooded with keyword-stuffed clone repos ("polymarket trading bot" spam READMEs) of unknown provenance — treat any repo that wants a private key as hostile until audited.

Infrastructure: Polymarket's origin is AWS eu-west-2 (London) behind Cloudflare. Official colocation in eu-west-2 exists but only for KYC/KYB-verified entities; individual operators therefore run VPSes in Dublin (eu-west-1, ~14–15ms feed p50, ~21–23ms order round-trip) or Amsterdam (~10ms feed) — locations chosen for latency AND because, per third-party guides (July 2026), Ireland, Japan, Malta (sports-only) and the Netherlands allow unrestricted API trading while the website is close-only (uncertain — vendor-sourced; verify against official ToS before relying on it). Order p99 runs 37–55ms across providers and the CLOB adds 70–85ms internal processing, so bot-vs-bot races are decided in tail latency; a single-strategy bot needs only 1–2 vCPU / 2–4GB RAM. WebSockets: /ws/market (public orderbook deltas) and /ws/user (authenticated fills/orders) with client-driven heartbeats every 10s; the /geoblock endpoint reports website eligibility, not API access. For the user's Rust/TS/Python monorepo: py-sdk or ts-sdk for strategy layer, real-time-data-client (TS) or raw websockets for feeds, polymarket-cli (Rust) as a reference implementation of V2 signing in Rust, and paper-mode-first bots (poly-maker, Xyryllium tracker) as governance-compatible starting points.

## Key findings
- CLOB V2 cutover happened April 28, 2026 (~11:00 UTC, ~1h trading pause): new contracts (ctf-exchange-v2), order books cleared, V1-signed orders and legacy SDKs dead in production. Any pre-2026 GitHub bot code is broken until ported.
- Collateral changed from bridged USDC.e to pUSD, an ERC-20 on Polygon backed 1:1 by native USDC, enforced onchain — the roadmap's 'USDC.e on Polygon' assumption is outdated as of April 2026.
- V2 order signing: removed nonce/feeRateBps/taker fields; added timestamp (ms), metadata, builder; EIP-712 Exchange domain bumped to version '2' while L1 ClobAuthDomain stays version '1' (chainId 137).
- Auth model unchanged in shape: L1 = one-time EIP-712 signature deriving apiKey/secret/passphrase via POST /auth/api-key; L2 = HMAC-SHA256 signature headers (timestamp in Unix seconds) on all authenticated calls. Signature types: EOA (0), Magic/email (1), browser proxy (2); Gnosis Safe supported in polymarket-cli.
- Rate limits (Cloudflare, sliding windows): 15,000 req/10s global REST; CLOB general 9,000/10s; POST /order 3,500/10s burst + 36,000/10min sustained (~60/s); DELETE /order 3,000/10s + 30,000/10min; batch /books|/prices 500/10s; single /book|/price|/midprice 1,500/10s; Gamma 4,000/10s (markets 300/10s, events 500/10s); Data API 1,000/10s (/trades 200, /positions 150); relayer /submit 25/min. Builder Program tiers (unverified/verified/partner via builder@polymarket.com) raise limits.
- Fees (global platform): fee-free through 2025, then taker fees phased in — crypto Jan 5, 2026; sports Feb 18; nearly all categories Mar 30, 2026; geopolitics permanently fee-free. Formula fee = C × p × feeRate × (p(1−p))^exponent, peaking at p=0.5; peak taker: crypto 1.80%, sports 0.75%, finance/politics 1.00%, economics 1.50%, culture/weather 1.25%. Makers pay $0.
- Maker Rebates Program: 20% (crypto) / 25% (most) / 50% (finance) of taker fees redistributed daily to makers pro-rata by filled maker volume; stacks with Liquidity Rewards. Note docs.polymarket.us (Polymarket US, separate CFTC-regulated exchange) has a different schedule (0.06 taker / 0.0125 maker coefficients, effective July 1, 2026) — do not conflate the two.
- Liquidity Rewards Program mechanics: daily payout ~midnight UTC, $1/day minimum (non-rolling), quadratic scoring favoring quotes near midpoint, per-market min-size and max-spread published via API/order book, 3x penalty for single-sided quoting when midpoint is 0.10–0.90 and zero rewards at extreme prices — two-sided quoting is effectively mandatory for farming bots.
- Official SDK landscape (mid-2026): py-clob-client and clob-client (TS) ARCHIVED; replacements are py-clob-client-v2 (166★) / clob-client-v2 (76★), and unified SDKs Polymarket/py-sdk (102★, `pip install polymarket-client`, sync+async, Gamma+Data+CLOB+WS, experimental perps API) and Polymarket/ts-sdk (30★). Polymarket/real-time-data-client (TS, 226★) for streaming; Polymarket/polymarket-cli (Rust, 2.8k★) does full trading with JSON output explicitly 'for scripts and agents' — best Rust V2 signing reference for the user's monorepo.
- Official agents: Polymarket/agents (Python, LangChain+Chroma RAG+OpenAI, 3.8k★) was ARCHIVED May 11, 2026; successor direction is Polymarket/agent-skills (181★, Claude-oriented skill docs: auth, trading, market data, websockets, split/merge/redeem, bridging, gasless relayer). Polymarket/poly-market-maker (Python bands/AMM keeper, 321★) remains the canonical but dated official MM reference.
- IMDEA Networks study (86M bets, Apr 2024–Apr 2025): $39,587,585 total arbitrage extracted; negRisk rebalancing = $28.99M (~73%) across just 662 markets vs $10.58M across 7,051 single-condition markets (claimed 29× capital efficiency); ~73% of profits captured by sub-100ms bots; combinatorial (LLM-detected dependency) arb was only 0.24% of profits.
- Cross-venue arb is a real, documented niche: Polymarket-vs-Kalshi (e.g. Celtics example Apr 2026: 0.97 combined cost, 3.09% gross, ~1.8% net after fees) and Polymarket-vs-bookmaker via de-vigged odds from The Odds API. kachence/polymm is the most credible open example: sports de-vig quoting + hedge, ~$5k net early 2026 on a public wallet, retired because Python was too slow — author now runs a private Rust rewrite.
- Latency/news bots target 5/15/60-min crypto up/down markets, exploiting 2–10s lag between Binance spot and Polymarket odds (learningworship/polymarket-latency-bot, PolyBullLabs sniper). These are the most fee-impacted (crypto = 1.80% peak taker) and most latency-competitive strategies.
- Copy trading works off the public Data API (data-api.polymarket.com: positions, trades/activity, leaderboards, PnL — no auth) plus CLOB WebSocket for execution. Open examples: Xyryllium/polymarket-tracker-bot (Node.js Discord bot, paper trading with configurable balance, liquidity/spread/slippage filters, stop-loss via WS), iengineer whale bot; commercial Telegram equivalents: Polycule, PolyFocus, PolyxBot.
- Infrastructure: origin in AWS eu-west-2 (London) behind Cloudflare; official colocation only via KYC/KYB business verification. Individual operators use Dublin eu-west-1 (~14–15ms feed p50, 21–23ms order RTT) or Amsterdam (~10ms feed) VPSes; order p99 37–55ms across providers; CLOB adds 70–85ms internal processing; 1–2 vCPU / 2–4GB RAM suffices for a single-strategy bot. WS channels /ws/market (public) and /ws/user (authed) need client heartbeats every 10s.
- Per third-party (vendor) guides as of July 2026: Ireland, Japan, Malta (sports-only), Netherlands allow unrestricted API trading with website close-only; US/UK/Germany/France are close-only on both frontend and API. The /geoblock endpoint reports website eligibility, not API status. UNCERTAIN — sourced from VPS vendors with commercial interest; verify against Polymarket's official ToS/docs.

## Pitfalls
- Pre-April-2026 code is dead code: the vast majority of GitHub Polymarket bots (including most found in searches) predate CLOB V2 and will fail signature validation in production (removed nonce/feeRateBps/taker fields, Exchange domain v2). Budget porting time; only trust repos that explicitly say V2 / py-clob-client-v2 / unified SDK.
- GitHub is heavily polluted with keyword-stuffed clone repos (READMEs repeating 'polymarket trading bot' dozens of times, e.g. samanalalokaya/*, Benjam1nCup/*, dev-protocol/*) that exist to farm search traffic or lure users into running unaudited code with private keys. Never run a bot repo against a funded wallet without reading every line that touches the key; prefer detection-only tools first.
- Adverse selection is the documented killer of naive MM/reward-farming: quotes that score highest rewards sit exactly where informed flow hits. kachence/polymm's own reconciliation showed theoretical arb of +$8,293 reduced by −$3,184 adverse-selection losses on residuals. Reward farming returns also dilute as more farmers split fixed per-market pools; $1/day minimum payout per day does not roll over.
- Fees now break old arb math: taker fee peaks at p=0.5 (up to ~1.80% in crypto markets), so thin cross-venue and negRisk edges computed from 2024–2025 data are overstated. Geopolitics markets remain fee-free — fee-sensitive strategies should account per category. Also don't confuse docs.polymarket.us (Polymarket US, separate CFTC-regulated exchange, own fee schedule) with the global platform.
- Latency competition is severe and Python is marginal: IMDEA found ~73% of arb profits go to sub-100ms bots; measured bot-vs-bot races are decided in 37–55ms p99 tails; the one transparent profitable operator retired his Python bot for a private Rust rewrite. The CLOB itself adds 70–85ms internal processing, so a solo operator cannot win pure speed races — pick edges (odds modeling, reward farming, copy filters) that don't require winning them.
- Rate limits are Cloudflare sliding windows with queuing-then-429 behavior; the relayer is only 25 req/min. Use batch endpoints and WebSockets (client heartbeats every 10s or you get disconnected), watch X-RateLimit-* headers, and implement exponential backoff with jitter.
- Geo/jurisdiction claims from VPS vendors (Ireland/Japan/Malta/Netherlands = API-unrestricted) are commercially motivated and unverified against official Polymarket ToS; the /geoblock endpoint reports website eligibility, not API access, so testing it is misleading in both directions. The Polymarket/agents ToS note also restricted certain jurisdictions from API trading. Legal review needed for the user's 'operate from outside Brazil' plan — do not rely on this research for that determination.
- docs.polymarket.com was unreachable (DNS timeout) from this research environment on 2026-08-15 — possibly transient, possibly geo-fencing (uncertain). Mirror critical docs locally and don't hard-depend on doc-site availability at runtime.
- pUSD migration nuances: existing balances required a conversion approval and all order books were wiped at cutover; historical strategies assuming USDC.e balances/allowances (and the old negRisk adapter approval flow at 0xd91E80cF...) need re-verification against V2 contract addresses.
- Claims in low-star repos (e.g. '$25/hour simulated profit', '61–68% whale predictive accuracy', '29× capital efficiency') are self-reported or extrapolated from the IMDEA dataset, not audited live results — treat as hypotheses to test in paper trading, not expected returns.
